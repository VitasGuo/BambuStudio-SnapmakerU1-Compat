## 已知问题

### #1 LLM 无法精确计算几何路径

- **现象**: LLM 生成的路径坐标与模型实际几何不匹配，导致 G-code 中的路径偏离模型轮廓
- **根因**: LLM 缺乏精确的空间几何计算能力，无法从面片数据推算出精确的截面轮廓路径
- **解决方案**: 必须使用 CLI 工具 `voxelflow` 获取 RawPath 数据，AI 仅基于 RawPath 生成 G-code，不可自行计算路径

### #2 E 值计算精度有限

- **现象**: LLM 计算的 E 值（挤出量）与理论值存在偏差，可能导致挤出不足或过度挤出
- **根因**: 浮点数计算精度限制，以及 LLM 对连续累计计算容易产生累积误差
- **解决方案**: E 值计算需后处理验证，建议在 G-code 生成后通过 `review_gcode` 检查 E 值合理性，必要时通过 `patch_gcode` 修正

### #3 复杂模型支撑结构难以生成

- **现象**: 对于悬垂区域复杂、多方向需要支撑的模型，LLM 难以正确生成支撑路径
- **根因**: 支撑结构需要精确的几何计算（支撑柱位置、分支角度、接口层），超出 LLM 的空间推理能力
- **解决方案**: 支撑路径必须由 CLI 工具生成（RawPath 中的 support 字段），AI 仅负责决定支撑类型和参数，不直接生成支撑路径

### #4 长时间生成容易丢失上下文

- **现象**: 层数较多的模型（>200 层）在生成 G-code 时，LLM 可能在中途丢失上下文，导致后续层格式不一致
- **根因**: LLM 的上下文窗口有限，长输出中容易遗忘前面的格式约定
- **解决方案**: 分段生成，每段包含明确的格式说明；使用模板确保格式一致性

### #5 耗材切换参数遗漏

- **现象**: 多耗材打印时，工具切换（T0→T1）后可能遗漏温度、回抽等参数更新
- **根因**: 工具切换涉及多个参数联动（温度、回抽长度、风扇策略），容易遗漏
- **解决方案**: 工具切换时使用检查清单，确保所有关联参数同步更新
